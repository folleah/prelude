## MODIFIED Requirements

### Requirement: Генерация файлов
Prelude SHALL генерировать файлы для выбранного harness из проверенного плана, исключая учётные данные. Правила проекта SHALL включать описание проекта и назначение выбранных внешних скиллов со ссылками на источники. Для поддерживаемого локального описания скилла SHALL генерироваться SKILL.md.

#### Scenario: Запуск агента после сборки
- **WHEN** пользователь открывает собранный проект в Codex
- **THEN** агент может получить описание и назначение выбранных скиллов из AGENTS.md

#### Scenario: Разные harness
- **WHEN** один план представлен в поддерживаемых форматах двух harness
- **THEN** каждый набор использует поддерживаемые этим harness имена, пути и структуру

### Requirement: Предпросмотр и запись
Prelude SHALL проверять создание и изменение файлов перед записью. При конфликте SHALL показываться список, diff и выбор между сохранением или заменой. Запись SHALL ограничиваться корнем проекта, проверять актуальность предпросмотра и обрабатывать частичный сбой.

#### Scenario: Сборка без конфликта
- **WHEN** пользователь запускает Build project и все изменения готовы к применению
- **THEN** Prelude выполняет запись напрямую

#### Scenario: Изменение после предпросмотра
- **WHEN** целевой файл изменился перед применением
- **THEN** запись блокируется до нового предпросмотра

#### Scenario: Выход за пределы корня
- **WHEN** целевой путь выходит из каталога через навигацию или ссылку
- **THEN** запись отклоняется

#### Scenario: Подтверждённое применение
- **WHEN** план проверен, конфликты разрешены и предпросмотр актуален
- **THEN** записываются только согласованные файлы

### Requirement: Создание проекта в пустой папке
Prelude SHALL записывать конфигурацию в выбранную существующую пустую папку с сохранением структуры каталогов и добавлять prelude.yaml при наличии состояния рабочего пространства.

#### Scenario: Папка занята
- **WHEN** перед записью выясняется, что папка не пуста
- **THEN** создание отклоняется либо пользователю предлагается сценарий разрешения конфликтов

#### Scenario: Создание проекта из идеи
- **WHEN** пользователь выбирает заранее созданную пустую папку и запускает Build project
- **THEN** Prelude записывает в папку проверенную конфигурацию и состояние проекта

#### Scenario: Папка занята или отсутствует
- **WHEN** выбранная папка отсутствует или содержит хотя бы один файл или вложенную папку
- **THEN** создание проекта отклоняется


## ADDED Requirements

### Requirement: Доступность действия Build project
Кнопка Build project SHALL отображаться поверх канваса при наличии хотя бы одного элемента и SHALL инициировать создание или применение действующего плана.

#### Scenario: Пустая схема
- **WHEN** канвас ещё не содержит элементов
- **THEN** кнопка Build project скрыта

### Requirement: Настройка зависимостей и памятка
Для npm-проекта с подходящим package-lock.json Prelude SHALL пытаться выполнить установку зависимостей после записи. Для компонентов с ручными шагами SHALL формироваться MAKE_ME_HARNESS_SETUP.md с версиями и ссылками.

#### Scenario: Ошибка установки
- **WHEN** конфигурация записана, но установка npm завершилась ошибкой
- **THEN** Prelude сообщает об ошибке установки и показывает дальнейшие шаги по подготовленной папке

### Requirement: Действия после сборки
После успешной записи Prelude SHALL показывать папку проекта, команду запуска выбранного harness и файл инструкций для агента. При наличии ручной настройки SHALL указываться файл памятки.

#### Scenario: Сборка для Claude Code
- **WHEN** конфигурация записана
- **THEN** диалог предлагает запустить claude в папке проекта и указывает CLAUDE.md
