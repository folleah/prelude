## Context

Этот change документирует состояние Prelude после серии изменений. Исходные требования к планированию и конфигурации уже опубликованы в основном наборе OpenSpec. Открытый `redesign-desktop-workflow` содержит промежуточное описание локального рабочего пространства и канваса.

## Goals / Non-Goals

**Goals**

- Связать фактические сценарии входа, создания проекта, построения схемы и выдачи конфигурации с проверяемыми требованиями.
- Зафиксировать изменения, которые уже реализованы в приложении.

**Non-Goals**

- Самодостаточное хранение метаданных всех внешних скиллов в `prelude.yaml` и отключение фоновой синхронизации обсуждались отдельно. Сейчас схема хранит ссылки на модули через их идентификаторы и версии, а каталог остаётся доступен планировщику.
- Глобальное ранжирование skills.sh и автоматический учёт звёзд GitHub в отборе пока отсутствуют. Поиск по задаче использует установочные счётчики найденных скиллов.
- Эта запись не архивирует и не синхронизирует ранее открытый change.

## Decisions

- Vue разносит вход, проекты, создание, конструктор и настройки по отдельным экранам. Канвас отображает данные схемы и открывает инспектор. Чат принимает изменения.
- Экран входа выбирает форму ChatGPT или API-ключа. Сохранённые сессии восстанавливаются через команды Tauri. Общая кнопка выхода удаляет обе сессии, поскольку приложение может восстановить любую из них.
- Discovery принимает обычный текст, а планирование принимает YAML-операции и применяет их локально. Для исправления формата предусмотрено до двух запросов с сохранением назначения ответа.
- Локальный каталог сочетает встроенные записи, пользовательские расширения и кэш. Поисковый запрос к skills.sh выполняется в рамках операции чтения каталога. Результаты проверяются по наличию SKILL.md и привязываются к версии GitHub.
- Сборка сохраняет конфигурацию в выбранной папке. Исправлять конфликты пользователь может перед записью. В инструкции выбранного harness добавляются описание проекта и сведения о внешних скиллах, а памятка перечисляет ручные шаги.
- В `prelude.yaml` сохраняется состояние проекта. Наличие прежней секции `settings` допускается при импорте, при сохранении она исключается.

## Risks / Trade-offs

- Полный набор удалённых скиллов зависит от состояния локального кэша и сети. Популярность используется как вспомогательный сигнал при выборе.
- Формат и структура плана проверяются локально. Рекомендации модели по полноте инфраструктуры остаются инструкциями в промпте.
- Позднейшие дельты канваса и YAML пересекаются с требованиями `redesign-desktop-workflow`. При синхронизации обоих changes нужно сохранить актуальный сценарий редактирования через чат и отсутствие секции `settings`.
- История проверок включает сборку, тесты отдельных веток и запуск Codex на тестовом проекте. Она не покрывает визуальную проверку каждого экрана или все живые интеграции с провайдерами.
