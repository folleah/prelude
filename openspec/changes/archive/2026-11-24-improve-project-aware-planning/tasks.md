## 1. Сценарии и базовая оценка

- [x] 1.1 Зафиксировать версию текущего промпта и подготовить обезличенные сценарии блога, Symfony с существующим API 1С и историей товаров, мобильного клиента с бэкендом, десктопного инструмента и игры. Для каждого записать входные данные и наблюдаемые критерии достойного плана.
- [x] 1.2 Подготовить повторяемый способ парного прогона. Проверить, что обе версии используют одну модель, одинаковые параметры, входные данные и снимок каталога. Зафиксировать результаты базового прогона.

## 2. Промпт планирования

- [x] 2.1 Перестроить промпт вокруг требований, компонентов, первой проверяемой задачи и зависимостей между рабочими потоками. Проверить в сценариях, что роли появляются по необходимости, параллельность обоснована и каждый модуль связан с работой.
- [x] 2.2 Уточнить выбор и описание проверок. Проверить, что быстрая проверка отражается коротким хуком, зависимые от внешней среды проверки имеют отдельное условие запуска, а неподтверждённые команды не выдаются за существующие.
- [x] 2.3 Проверить через штатный путь планирования, что результат сохраняет формат YAML и проходит локальную валидацию. На сценарии точечного изменения проверить сохранение несвязанных ролей, модулей, инструкций и хуков.

## 3. Сравнение

- [x] 3.1 Прогнать обновлённый промпт на тех же пяти сценариях и сопоставить результаты по сохранности требований, осуществимости первой задачи, обоснованности ролей и модулей, применимости проверок. Записать конкретные улучшения и регрессии.
- [x] 3.2 Устранить найденные регрессии промпта и повторить затронутые прогоны. Проверить, что вывод о качестве подтверждается сравнением и что локальные тесты проходят.
