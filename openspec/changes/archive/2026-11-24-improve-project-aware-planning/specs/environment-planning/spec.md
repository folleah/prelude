## ADDED Requirements

### Requirement: План агентной разработки с учётом проекта

Начальный план SHALL связывать требования пользователя и признаки репозитория с компонентами проекта, первой проверяемой задачей, инструментами, скиллами и проверками. Планировщик SHALL отличать подтверждённые факты от допущений и сохранять явные технологические ограничения. План смешанного проекта SHALL учитывать зависимости между его частями.

#### Scenario: Интеграция с внешней системой и веб-интерфейс
- **WHEN** пользователь описывает Symfony-приложение с существующим API 1С, историей товаров и локальными аккаунтами
- **THEN** план сохраняет все четыре требования и связывает первую рабочую задачу, границы ответственности и проверки с этими требованиями

#### Scenario: Простой проект
- **WHEN** одна роль может выполнить весь объём работ и пользователь не требует дополнительных ролей
- **THEN** план описывает один рабочий поток и выбирает модули с конкретным применением

#### Scenario: Приложение с клиентом и бэкендом
- **WHEN** пользователь описывает приложение с несколькими связанными частями
- **THEN** план раскрывает зависимости и отмечает параллельность только для задач, которые можно выполнять независимо после необходимых согласований

#### Scenario: Точечное изменение существующего плана
- **WHEN** пользователь просит изменить одну часть уже настроенного проекта
- **THEN** планировщик сохраняет несвязанные роли, модули, инструкции и проверки

### Requirement: Короткие проверки по контексту проекта

Начальный план SHALL явно указывать применимые хуки как короткие действия с условиями запуска. Для нового программного проекта модель SHALL рассматривать быстрые тесты до появления команды запуска. Если под проектом уже есть подтверждённая команда, план SHALL учитывать её. Хуки SHALL сохранять нейтральные к харнессу названия и описания.

#### Scenario: В репозитории есть подходящая проверка
- **WHEN** в переданном контексте репозитория подтверждена команда быстрого тестирования
- **THEN** план предлагает её для релевантных изменений и учитывает область проверки

#### Scenario: Тесты пока не настроены
- **WHEN** для нового программного проекта подходит быстрая проверка, но команды ещё нет
- **THEN** план может предложить её в виде короткого хука и отмечает, что запуск предстоит настроить

#### Scenario: Проверка зависит от внешней среды
- **WHEN** проверка требует настоящих учётных данных, интерактивного устройства или длительного прогона
- **THEN** план указывает условия её отдельного запуска и предлагает быструю локальную проверку там, где она применима
