# Сравнение промптов

Сценарии и исходные промпты лежат в `src-tauri/tests/fixtures/planning/`. Тест `compare_planning_prompts` отправляет по два запроса на сценарий. Пары используют одну модель, одинаковый вход, параметры запроса и снимок каталога. Каталог включается в контекст обеих версий целиком, чтобы результаты поиска не менялись между запросами. В выводе есть модель, хеш каталога, критерии, ответ в YAML и результат локальной валидации.

Задайте в локальном окружении `PRELUDE_EVAL_MODEL` и выберите способ подключения. В Windows для сохранённой сессии ChatGPT задайте `PRELUDE_EVAL_CHATGPT_STORAGE` с путём к папке данных Prelude. Тест использует штатное восстановление сессии. Для HTTPS Chat Completions задайте `PRELUDE_EVAL_ENDPOINT` и `PRELUDE_EVAL_API_KEY`. Прогон расходует квоту модели. Учётные данные не выводятся.

```powershell
cargo test --offline --manifest-path src-tauri/Cargo.toml compare_planning_prompts -- --ignored --nocapture
```

Для каждой пары запишите наблюдения по критериям сценария. Дополнительно проверьте, сохраняются ли обязательные требования, можно ли начать и проверить первую задачу, имеют ли все роли и модули конкретное назначение и соответствует ли условие запуска каждой проверки проекту.

## Состояние

Локальный тест проверил равенство входа в паре и применение YAML-операций через текущий парсер и валидатор.

Полный парный прогон выполнен через сохранённую сессию Prelude на `gpt-6.2-sol`. SHA-256 каталога — `b1d038c29ae4ffa25a45d539ae4a4189d1e84709085b07b13c4f0def592ba1bb`. Все десять ответов прошли локальную валидацию.

| Сценарий | Наблюдение |
| --- | --- |
| Блог | Обе версии оставили одну роль и статический сайт. Новая версия отделила первую задачу и критерии: сборка двух страниц, рабочая ссылка и отрендеренный Markdown. |
| Symfony и 1С | Обе версии сохранили требования и предложили PHPUnit с тестовыми данными. Новая версия первой задачей проверяет вход, отображение двух наблюдений и отсутствие дубля при повторном импорте. Живой API выделен в отдельную проверку. |
| Мобильный клиент и бэкенд | Обе версии описали синхронизацию и разделили локальные и аппаратные проверки. Новая версия явно задала первый офлайн-сценарий, но объединила клиент и бэкенд в одну роль. Базовая выделила независимые роли после согласования контракта. |

В системный промпт добавили оценку независимости по всему проекту, включая задачи после первой проверяемой поставки. Для повторного прогона одного сценария можно задать `PRELUDE_EVAL_CASE`, например `mobile-backend`.

Повторная мобильная пара использовала ту же модель и тот же хеш каталога. Оба ответа прошли валидацию. Новый план выделил Android и бэкенд в отдельные роли, согласовал версионированный контракт и общие тестовые данные перед параллельной работой и сохранил разделение быстрых и аппаратных проверок. Это подтверждает исправление в проверенном сценарии. Один прогон на сценарий не позволяет оценить стабильность при повторных запросах или на других моделях.
