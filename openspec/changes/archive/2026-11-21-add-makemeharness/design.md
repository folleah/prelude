## Context

В приложении уже есть локальный каталог, форма профиля и проверка плана. Требования описаны в [подборе окружения](specs/environment-planning/spec.md) и [выдаче конфигурации](specs/configuration-delivery/spec.md).

## Goals / Non-Goals

- Воспроизводимая локальная проверка и генерация файлов при одинаковом плане и версии каталога.
- Единая модель плана для редактирования, проверки, предпросмотра и экспорта.
- Граница интеграции заканчивается на конфигурационных файлах. Установка сторонних инструментов и управление их процессами остаются вне приложения.

## Decisions

1. **Разделение UI и ядра.** Vue 3, TypeScript и Tailwind CSS отвечают за ввод, редактор и diff. Tauri предоставляет узкие типизированные команды. Rust владеет доступом к файловой системе, секретами, сетью, проверкой и записью. Вариант с доступом WebView к файловой системе увеличивает привилегии интерфейса.
2. **Версионированный локальный реестр.** Поставляемый каталог и отдельный пользовательский слой загружаются через общую схему. Запись содержит ID, тип, версию схемы, источник, диапазоны поддерживаемых версий, требования, конфликты и метаданные стоимости при наличии. Пользовательские записи добавляются по уникальному ID. Декларативные записи интерпретируются как данные. Плагины с исполняемым кодом увеличивают поверхность доверия.
3. **План от ИИ.** Приложение формирует запрос с профилем проекта, бюджетом, приоритетом и карточками локального каталога. При подключении через подписку Tauri открывает официальный Sign in with ChatGPT в системном браузере. После согласия на использование подписки Rust устанавливает сеанс по документированному потоку для open-source клиентов и автоматически получает структурированный план через Responses API. Альтернативное подключение использует API-ключ, выбранную модель и endpoint провайдера. Для сторонних OpenAI-совместимых API доступны пользовательские HTTPS endpoint и ID модели. Другие форматы API подключаются через адаптеры провайдеров. Провайдер должен поддерживать вызовы инструментов. Rust хранит ключ в памяти сеанса либо в защищённом хранилище ОС и отправляет его только выбранному endpoint. MakeMeHarness выступает локальным MCP-хостом: операции чтения каталога сопоставляются с function tools, а вызовы выполняются локально по MCP. Пользователь подтверждает состав отправляемого контекста в приложении. Ключи, токены, пути и содержимое файлов проекта не передаются в контексте. Выход из аккаунта очищает локальные учётные данные. ИИ определяет состав окружения и объясняет выбор. Rust проверяет идентификаторы, версии и совместимость, затем рассчитывает эксплуатацию по известным тарифам и квотам. Расходы на планирование показываются отдельно от бюджета эксплуатации. MCP ограничен чтением каталога. Проверка плана, предпросмотр и подтверждение записи остаются в MakeMeHarness.
4. **Единый план и адаптеры выдачи.** План хранит выбранные версии, роли, обоснования и ссылки на записи каталога. Правила по возможности объединяются в одном поддерживаемом месте с учётом области действия. Адаптеры Codex, Claude Code и OpenCode преобразуют план в карту относительных путей и содержимого. Матрицу поддерживаемых версий и шаблоны при реализации сверить с документацией проектов и закрепить тестовыми примерами. Универсальный шаблон затрудняет соблюдение различий форматов.
5. **Единый снимок для предпросмотра и доставки.** Rust связывает предпросмотр с версией плана, идентичностью корня и хешами исходных файлов. При записи повторно проверяет пути, включая symlink и reparse point, и обнаруживает изменение файлов. Временные файлы готовятся заранее, а журнал с оригиналами позволяет откатить частичную запись и восстановиться после прерывания. Для существующих пользовательских файлов явное разрешение конфликта входит в предпросмотр. Создание проекта использует тот же снимок и проверенные относительные пути. Пользователь заранее создаёт пустую папку и выбирает её до подтверждения. Rust повторно проверяет, что папка существует и пуста перед созданием файлов. Прямая запись по данным из UI допускает расхождение с ранее просмотренным содержимым.

## Risks / Trade-offs

Экран «Подключение ИИ» показывает две карточки. В карточке ChatGPT доступны вход, текущий статус аккаунта и отключение. В карточке API доступны выбор провайдера, включая OpenRouter и пользовательский endpoint, поле ключа с маскировкой и выбор модели. Для активного подключения доступны выбор модели из поддерживаемых вариантов и кнопка «Проверить подключение». Настройки, которые поддерживает выбранный провайдер, можно раскрыть отдельно. На экране явно указано, какое подключение используется для подбора.

- Изменение тарифов, квот и форматов → датировать сведения и показывать неподтверждённые позиции. Проверять адаптеры на зафиксированных версиях.
- Недоверенный текст репозитория и ответы моделей → ограничить контекст, проверять структурированный ответ и исключить выдачу команд на выполнение.
- Различия файловых систем → проверить регистр, допустимость имён, ссылки и восстановление на каждой целевой ОС.
- Доступность моделей → передавать ИИ только сведения о доступе, заявленные пользователем.

## Migration Plan

Выпустить первую версию с встроенным каталогом, инструкциями для сборки и лицензией open source. Миграция данных приложения не требуется. Для изменений в пользовательских проектах предусмотреть восстановление по журналу записи.
