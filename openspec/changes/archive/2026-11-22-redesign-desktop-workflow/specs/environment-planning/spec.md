## MODIFIED Requirements

### Requirement: Входные данные
Приложение SHALL принимать описание идеи или выбранный локальный репозиторий, доступные провайдеры и модели, бюджет с валютой и периодом и приоритет между экономией и качеством. Описание идеи SHALL вводиться в чате слева от конструктора. Новый проект SHALL открываться с пустыми зонами и готовым к вводу чатом.

#### Scenario: Проект без репозитория
- **WHEN** пользователь отправляет описание из чата нового проекта
- **THEN** приложение после согласия запрашивает план по описанию и заполняет открытый конструктор редактируемыми рекомендациями и допущениями ИИ

#### Scenario: Локальный репозиторий
- **WHEN** пользователь выбирает каталог
- **THEN** приложение извлекает признаки проекта без выполнения его кода или изменения файлов

### Requirement: Обмен планом с ИИ
Приложение SHALL открывать отдельный экран подключения при отсутствии действующего сеанса и давать выбор между официальным входом через ChatGPT с разрешением на использование подписки и подключением к выбранному ИИ-провайдеру по пользовательскому API-ключу. Для подключения по ключу приложение SHALL принимать модель и пользовательский HTTPS endpoint OpenAI-совместимого API. Ключ SHALL храниться только в памяти сеанса либо в защищённом хранилище ОС. После согласия на отправку контекста приложение SHALL автоматически передавать ИИ описание или признаки проекта, приоритет и бюджет, предоставлять чтение локального каталога через MCP и получать структурированный план. Учётные данные, пути и содержимое файлов репозитория SHALL исключаться из контекста. Проверка и выдача плана SHALL выполняться локально.

#### Scenario: Успешное получение плана
- **WHEN** пользователь вошёл с доступной подпиской, подтвердил отправку контекста и ИИ вернул план с известными идентификаторами модулей
- **THEN** приложение открывает план для проверки и редактирования в конструкторе

#### Scenario: Подключение по API-ключу
- **WHEN** пользователь указывает API-ключ, модель и совместимый endpoint и подтверждает отправку контекста
- **THEN** приложение автоматически запрашивает план у выбранного провайдера и предоставляет модели те же операции чтения каталога через MCP

#### Scenario: Настройки подключения
- **WHEN** пользователь открывает настройки ИИ
- **THEN** приложение показывает статус активного подключения и проверку соединения
- **AND** модель для запросов MakeMeHarness выбирается под полем чата из списка активного провайдера, без поля ручного ввода

#### Scenario: Выбор способа входа
- **WHEN** пользователь переключает вариант в селекторе подключения
- **THEN** экран показывает элементы выбранного варианта, кнопку входа и статус для ChatGPT или выбор OpenRouter либо своего провайдера и маскированное поле ключа для API
- **AND** поле HTTPS endpoint доступно при выборе своего провайдера

#### Scenario: Восстановленный сеанс
- **WHEN** сохранённое подключение успешно восстановлено
- **THEN** приложение открывает рабочее пространство

#### Scenario: Неизвестный модуль или повреждённый ответ
- **WHEN** ответ не соответствует формату или содержит идентификатор вне каталога
- **THEN** приложение показывает причину, сохраняет текущий план и исключает неизвестный модуль из генерации файлов

## ADDED Requirements

### Requirement: Визуальный конструктор окружения
Конструктор SHALL показывать блок «ИИ и модели» сверху и четыре вертикальные зоны ниже — «Оркестрация», «Harness», «Skills и плагины», «Инструменты и сервисы». Зоны SHALL оставаться видимыми при пустом составе. Пользователь SHALL иметь возможность добавлять, заменять и удалять карточки и назначать каждой роли модель из набора проекта.

#### Scenario: Сведения о модуле
- **WHEN** пользователь выбирает карточку на полотне
- **THEN** справа показываются сведения о выбранном модуле
- **AND** по умолчанию и после клика по пустой области полотна правая панель пуста

#### Scenario: Пустая зона
- **WHEN** в зоне нет карточек
- **THEN** зона показывает название, назначение и кнопку добавления, открывающую соответствующую категорию каталога или редактор роли

#### Scenario: Несколько моделей проекта
- **WHEN** пользователь добавляет несколько моделей в верхнем блоке
- **THEN** он может назначить разным ролям разные модели или использовать одну модель для нескольких ролей

#### Scenario: Изменение окружения
- **WHEN** пользователь заменяет harness, удаляет назначенную модель или меняет компонент
- **THEN** конструктор показывает затронутые зависимости и назначения на соответствующих карточках и позволяет исправить их
