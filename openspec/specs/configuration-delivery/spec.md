# configuration-delivery Specification

## Purpose

Получение проверенной конфигурации в виде локальных файлов существующего или нового проекта.

## Requirements

### Requirement: Генерация файлов
Prelude SHALL готовить один самодостаточный Markdown-файл по проверенному плану. Имя SHALL быть `AGENTS.md` для Codex и OpenCode и `CLAUDE.md` для Claude Code. Текст SHALL включать описание проекта, выбранные инструменты, роли при наличии, действия первого запуска, зависимости, шаги настройки и проверяемые критерии готовности. Для каждого выбранного скилла SHALL указываться его назначение, условия применения, способ найти локальную копию или подключить внешнюю и известный источник с ревизией, если она доступна. Учётные данные SHALL исключаться. Подготовка проекта агентом SHALL начинаться по просьбе пользователя.

#### Scenario: Запуск агента после сборки
- **WHEN** пользователь открывает проект в Codex и просит подготовить окружение
- **THEN** инструкции в AGENTS.md позволяют начать работу без чтения prelude.yaml

#### Scenario: Разные harness
- **WHEN** пользователь готовит инструкции для Codex, Claude Code или OpenCode
- **THEN** Prelude выбирает имя и формат файла, который читает соответствующий агент

#### Scenario: Правило применения Humanizer
- **WHEN** Humanizer выбран для сайта с публичными текстами
- **THEN** инструкция указывает этапы работы, на которых его следует применять, и как получить его инструкции

### Requirement: Предпросмотр и запись
Prelude SHALL показывать полный текст и имя целевого файла до записи. Копирование SHALL передавать полный текст в буфер обмена. Сохранение SHALL происходить по явному действию пользователя. При отличающемся существующем файле SHALL показываться diff и требоваться подтверждение замены. Prelude SHALL проверять актуальность подтверждённой версии и ограничивать запись выбранной папкой проекта.

#### Scenario: Сборка без конфликта
- **WHEN** пользователя устраивает предпросмотр и он сохраняет инструкции в папку без целевого файла
- **THEN** Prelude записывает показанный Markdown-файл

#### Scenario: Изменение после предпросмотра
- **WHEN** существующий файл изменился после показа diff
- **THEN** Prelude требует новый предпросмотр перед заменой

#### Scenario: Выход за пределы корня
- **WHEN** путь целевого файла через ссылку указывает за пределы проекта
- **THEN** запись отклоняется

#### Scenario: Подтверждённое применение
- **WHEN** пользователь подтвердил актуальный diff
- **THEN** Prelude сохраняет только показанный файл инструкций

#### Scenario: Копирование текста
- **WHEN** пользователь копирует инструкции из окна предпросмотра
- **THEN** буфер обмена получает весь показанный Markdown, а файлы проекта не изменяются

### Requirement: Создание проекта в пустой папке
Для нового проекта Prelude SHALL использовать выбранную существующую пустую папку. Предпросмотр SHALL открываться без записи, а явное сохранение SHALL создавать только файл инструкций. Сценарий подготовки инструкции для существующего проекта SHALL поддерживать непустую папку.

#### Scenario: Папка занята
- **WHEN** после проверки пустой папки в ней появился файл
- **THEN** Prelude не применяет режим создания без повторной проверки папки

#### Scenario: Создание проекта из идеи
- **WHEN** пользователь подготовил инструкции и сохраняет их в заранее созданную пустую папку
- **THEN** Prelude записывает файл инструкций, а состояние конструктора остаётся в локальном хранилище приложения

#### Scenario: Папка занята или отсутствует
- **WHEN** папка для нового проекта отсутствует или уже содержит файлы
- **THEN** новый проект в этой папке отклоняется, а для существующей непустой папки доступен сценарий открытия проекта

### Requirement: Доступность действия Build project
Действие «Подготовить инструкции» SHALL отображаться поверх канваса при наличии хотя бы одного элемента. Оно SHALL проверять план и открывать предпросмотр для допустимой конфигурации.

#### Scenario: Пустая схема
- **WHEN** канвас ещё не содержит элементов
- **THEN** действие подготовки инструкций скрыто

### Requirement: Настройка зависимостей и памятка
Prelude SHALL описывать установку зависимостей, подключение скиллов и способы локальной проверки в основном Markdown-файле. Выполнение этих операций SHALL оставаться задачей выбранного агента. Выдача SHALL исключать запуск установщиков и создание отдельной памятки.

#### Scenario: Ошибка установки
- **WHEN** агент выявляет сбой установки при подготовке проекта
- **THEN** инструкции требуют сообщить о конкретном сбое и шагах, которые требуют участия пользователя

#### Scenario: Проект с npm lockfile
- **WHEN** пользователь сохраняет инструкции для проекта с package-lock.json
- **THEN** Prelude сохраняет текст с рекомендациями для агента без запуска npm

### Requirement: Действия после сборки
Окно результата SHALL показывать директорию проекта, имя файла, полный текст инструкций и действия копирования и сохранения. Подготовка окружения SHALL быть описана в этом тексте как первая задача для агента.

#### Scenario: Сборка для Claude Code
- **WHEN** пользователь готовит инструкции для Claude Code
- **THEN** окно показывает полный текст CLAUDE.md и позволяет скопировать его или сохранить в проект
